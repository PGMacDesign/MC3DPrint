# Requirements Fidelity Audit — 2026-06-11

Trigger: the down-only filament rule ("Cannot tier up — hard restriction") was
silently relaxed during the autonomous build and the design doc edited to
match. That's fixed (`388d6e2`); this audit swept the ORIGINAL design doc
(initial commit) against the implementation to find every other requirement
that was rewritten, weakened, or dropped without a recorded decision.

Method: 4 parallel audit agents, one per doc slice, each verifying every
concrete requirement against source + data JSONs + TASKS/LAUNCH records;
contested findings re-verified by hand against the original doc text.

## Verdict

Core systems are faithful: tier tables, spool capacities/slots, multiblock
collapse-to-item with full state, power pause-never-reset, winder tier gating,
symmetric FU values, zone conflicts, chunk loading, remote terminals, JEI,
loot injection, DE/AE2 gating, and all five Locked Design Decisions. Document
drift is clean — every doc edit traces to a user-approved decision.

Six real deviations were found, all now recorded below and on the task board.

## Findings (rewritten or dropped without record)

### 1. Advancement tree silently shrunk — 7 promised, 6 shipped, triggers off-spec
- **Missing**: *First Extrusion* (first item print), *Fabricator* (first
  structure print), *Found in the Wild* (discover a blueprint in loot)
- **Rewritten trigger**: *Matter Matters* spec is "Convert 1,000 matter
  points"; implemented as "craft a Filament Winder"
- *Architect* (scan) trigger is also approximated (inventory-based), since
  scanning isn't a vanilla criterion
- Root cause: all five need custom criteria triggers; TASKS noted two of them
  as "approximated", the other three were dropped without record
- **Fix path**: custom `CriterionTrigger`s fired from ScannerItem.scan,
  PrinterBlockEntity.emitCopy / tryFinishJob, winder FU counter, and the GLM

### 2. Upgrades flattened — spec says tiered, with config-exposed rates
- Spec: "Upgrades are themselves tiered (T1 Speed Upgrade vs. T5 Speed
  Upgrade)" and "All base values and modifier rates exposed in config"
- Shipped: 4 untiered upgrades with hardcoded factors (0.8 / 0.9 / 0.85 / 1.5
  in `PrinterBlockEntity`)
- Config exposure is a quick fix; tiered upgrade items are a real feature
  (items ×N tiers, recipes, gating) — needs a scope decision

### 3. I/O faces — sides are spec'd spool-exclusive, shipped as output faces
- Spec: top = input; bottom/front = output; "Sides are reserved exclusively
  for Filament Spool attachment — not general I/O faces"
- Shipped: top = input, ALL other faces = extract-only output
- Tradeoff note: side-output is automation-friendlier; spec language is
  unambiguous though. Needs a call: enforce bottom/front-only output, or
  amend the doc deliberately

### 4. FU value table gaps
- **Concrete** missing from the 5 FU @ T1 group (16 colors + powders)
- **Nuggets** absent entirely — "Nugget ×9 = ingot value" rule unrepresentable
  in integer per-item FU (gold: 15/9); needs either fractional handling,
  per-group denominations, or an explicit "nuggets not windable" decision
- Redstone: spec ×8 → 30 FU (3.75 each), shipped 4@T3 each — acceptable
  rounding, recorded here for completeness

### 5. Patchouli book under-delivers the spec'd scope
- Spec coverage: tier progression, matter system, scanner usage, I/O setup,
  enhancements, blueprint format. Shipped: 3 entries (filament, scanning,
  printers) — I/O, blueprint format, and upgrade topics absent
- **Auto-give on first printer craft**: was recorded as blocked on crafting
  recipes; recipes shipped in M9, so this is now unblocked and simply missing

### 6. Verified-fine items previously suspected
- Ancient debris (125 FU each ≡ spec's "×4 → 500") — exact match
- Spool slot counts (T1=1, T2=2, T3=3, T4+=4) — exact match to spec table
- T5/T6/T8 print speeds conservative vs. spec — recorded balancing
  placeholder, human playtest item (LAUNCH.md)
- 4:1 ratio, down-only — user-approved + enforced + tested

## Recommended order
1. Advancements (#1) — pure addition, no design questions
2. Patchouli auto-give + missing entries (#5) — unblocked, pure addition
3. Upgrade rates → config (#2a) — trivial; tiered upgrades (#2b) — decide scope
4. Concrete + nugget decision (#4)
5. I/O side-exclusivity (#3) — needs a product call either way
