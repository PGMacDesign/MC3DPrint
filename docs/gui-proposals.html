1 · Filament Winder GUI

Today: 176×166 panel, input slot + spool slot, an RF bar (left) and FU gauge (right), a center progress arrow, and exactly two error states (a red X + one line of text). No live status text, no material/tier preview, the painted status LEDs are never lit, and the exact-tier rule is invisible — a tier mismatch just silently does nothing. That opacity is the core thing to fix.

The reel spins while winding (cadence follows RF, like the exterior animation) and stops/greys when idle — instantly legible "is it working?". Three info cards turn the winder from a black box into a readout: what's being wound, how full the spool is, and throughput.

  • New texture region + a few more data slots; medium effort.

Two tier chips with a link icon between them: green chain when tiers match, broken red chain when they don't, plus a one-line fix ("Insert a Tier 4 spool"). Directly targets the #1 new-player wall — the winder doing nothing with no explanation.
  • Best at teaching the exact-tier mechanic; great for first-time users.
  • Stays compact.
  • Less useful once you know the rules — fewer ongoing readouts than W-B.
My pick: W-B (Throughput Panel), folding in W-C's tier-match chips for the blocked state. You get the at-a-glance "is it running" reel, real throughput/spool readouts to match the printer's polish, and the match-gate chips solve the silent-mismatch confusion without a separate concept.

2 · Server Blueprint Repository

Today: the storage layer is fully built — BlueprintFileStore already does save / load / list / delete by UUID, curated builds auto-install, and discs carry cached metadata (name, size, tier, cost, official-vs-scanned). What's missing is a player-facing way to browse the store and burn any stored blueprint onto a blank disc — right now that only happens via creative tab, loot, scanning, or admin commands. These three concepts are the new block + GUI on top of that existing plumbing.

One screen does it all: scroll/search every stored build, click for full metadata + a preview pane, drop a blank disc and hit Burn to Disc. Official/scanned badges keep the resin anti-dupe rule visible (burning a scanned build yields a scanned disc).
  • Complete owner workflow in one place; closes the M9 deferral cleanly.

  • Widest panel + needs a metadata list payload synced to the client.

Turns the block into the server's blueprint control panel: everything in R-A plus management — rename a cryptic Scan @ x,y,z, delete junk scans, lock favourites, export to .schem (surfacing the existing /mc3dprint export in the GUI).
  • Best for server owners / curators; agent-native parity with the commands.
  • Reuses existing export + delete APIs directly.
  • Destructive actions need permission gating + confirm dialogs.
  • Heaviest scope of the three.
My pick: R-A (Library Browser) as the v1, designed so R-C's management actions can bolt on later. R-A delivers the missing core capability — browse the store, preview, burn to disc — with search/filters that scale to the full curated set, and it doesn't block on per-build thumbnail rendering the way R-B does. Rename/delete/export (R-C) can land as a follow-up behind a permission check.
