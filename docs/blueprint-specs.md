# MC3DPrint — Curated Blueprint Specs (Improved + Expanded Set)

> **Purpose.** A faithful, buildable spec for an improved + expanded curated
> blueprint set that *looks* like real overworld Minecraft builds, spanning more
> footprint tiers (T3–T8) and richer material/disc tiers (T1–T5+). Designs are
> **original / parametric** — they are generated by our own code in
> `src/test/java/com/pgmacdesign/mc3dprint/blueprint/CuratedBlueprintGenerator.java`.
> Nothing here is copied from a third-party schematic; the cited references are
> for *proportions and palette faithfulness only*.

## How to read this doc

- **Axes** (match the existing generator): `x` = width (east), `y` = up,
  `z` = depth (south). A roof slope rising toward `+z` uses stairs with
  `facing=south` on the north slope and `facing=north` on the south slope
  (this is the existing `gableRoofX` convention — verified against the code).
- **Footprint** is `W×L` (x by z). The **minimum printer tier** is the smallest
  `MachineTier` whose `maxFootprint ≥ max(W, L)`. The ladder is the hard gate:

  | Tier | `maxFootprint` | Largest square it prints |
  |------|----------------|--------------------------|
  | T1   | 0              | items only               |
  | T2   | 0              | items only               |
  | T3   | 3              | 3×3                      |
  | T4   | 5              | 5×5                      |
  | T5   | 9              | 9×9                      |
  | T6   | 15             | 15×15                    |
  | T7   | 23             | 23×23                    |
  | T8   | 33             | 33×33                    |

  > **Footprint rule of thumb.** A build's gating tier is driven by its **larger**
  > horizontal dimension. A `3×9` dock needs **T5** (because 9 > maxFootprint of T4),
  > even though it's only 3 wide. Every spec below states the implied tier explicitly.

- **Disc / material tier** (richness gate) = the **highest material tier of any
  single block** in the build. Mapping used throughout:

  | Material tier | Representative blocks |
  |---------------|-----------------------|
  | **T1** | cobblestone, dirt, grass, planks, logs, glass, wool, hay, oak fence, farmland, water, wheat |
  | **T2** | copper (block/cut/stairs/grate/bulb), iron block, iron bars, lantern (iron+nugget), chain, smithing table |
  | **T3** | redstone block/lamp, polished blackstone, target |
  | **T4** | emerald block, lapis block |
  | **T5** | diamond block, netherite block, beacon |
  | **T7** | nether star (beacon core), end-tier accents |

  Most current builds sit at **disc T1** (a few touch T2 via lanterns/iron). The
  expanded set deliberately pushes several builds to **T2–T5** so higher disc
  tiers are represented (see *Copper Observatory*, *Iron Foundry*, *Diamond Vault*,
  *Beacon Spire*).

### Systemic defects (apply across the set)

1. **Door facing is inverted everywhere.** Every `door(x,y,z,wood,"north")` is placed
   on a `z=0` (north) wall but `facing=north` makes the door open *away from* the
   interior incorrectly for that wall — a north wall door should be `facing=south`
   (it faces south, into the build, hinged to swing out). **Fix the `door()` helper's
   call sites or the convention**: for a wall on the `z=0` face, pass `facing=south`;
   for `z=zmax`, `facing=north`; for `x=0`, `facing=east`; for `x=xmax`, `facing=west`.
2. **1-tall fences** on `small_farm` and `animal_pen` read as curbs. Vanilla pens/
   farms use a single fence course **but on a raised lip or with a gate post taller**;
   our fences sit flush on the ground floor (`y=1`) with the field also at `y=0..1`,
   so they barely clear the crops. Raise functional fences to `y=1` on a `y=0`
   border lip (already present on the farm) — but the *gate facing* and *post height*
   need correcting.
3. **Floating light fixtures.** Hanging lanterns are frequently placed with nothing
   solid in the block above (`village_well`, `wooden_bridge`, `bell_tower`).
   `lantern[hanging=true]` needs a solid/fence block directly above or it visually floats.
4. **Roof/wall vertical gaps.** `watchtower_tall` (y=6 gap), `wall_gate_segment`
   (y=3 gap over doors), and corner-log nubs (`plains_house`, `bakery`, `blacksmith_hut`)
   all leave a 1-block discontinuity between wall top and roof/battlement.
5. **No genuinely high-material builds.** Richest block anywhere is a lantern/anvil/bell
   (disc T2). Nothing uses copper, iron blocks, redstone, emerald, or diamond — so the
   disc-tier readout never exceeds ~T2. The expanded set fixes this.

## 2. Design conventions for the new set

These tighten the existing helpers and add a few. **All specs below assume these.**

- **Door facing by wall:** north wall (`z=0`) → `facing=south`; south wall
  (`z=zmax`) → `facing=north`; west wall (`x=0`) → `facing=east`; east wall
  (`x=xmax`) → `facing=west`. (i.e. the door faces *into* the building's interior,
  which is how vanilla doors on an outer wall read when entering.)
- **Windows always include glass.** Use `glass_pane` for 1-wide openings in a wall
  (vanilla village style) and `glass` (full block) only for skylights/greenhouses.
  Never leave a hole. A "window" = swap the wall block for a pane, optionally with
  a 1-block sill of stairs/slab below outside.
- **Roofs must close.** A gable from `gableRoofX` must start at the **wall-top course**
  (`yBase = wallTop`) with **no `y` gap**, and the **gable ends** (the triangular
  `z`-facing faces) must be filled with the wall material so the attic isn't open.
  The current `gableRoofX` leaves the two triangular gable ends open — add a
  `gableEndFill` helper (see §5).
- **Corner posts = wall height**, not wall+1. Run `corners(...)` to the same `yTop`
  as `walls(...)` so no log nub pokes out, *unless* deliberately making an exposed
  timber frame (manor) where the post should still terminate at the plate.
- **Functional fences are 1 course on a raised lip**, gate facing **out** of the
  enclosure (a pen gate on the north wall `z=0` faces `north`, i.e. outward — the
  opposite of door convention, because you walk *out* through a pen gate).
- **Lanterns need backing.** A `hanging=true` lantern requires a solid block, fence,
  or chain in the cell directly above. A `hanging=false` lantern sits on a floor/slab.
- **Material-tier intent is explicit.** Each build states its disc tier; high-tier
  builds concentrate the rich block in a single signature feature (a copper roof, an
  iron-bar forge, a diamond block vault core) so the build still reads as common
  Minecraft, just *trimmed* with the rich material.

### 3.1 `well` — village_well (improved)

- **Display name:** Village Well
- **Footprint / H:** `5×5×6` → **printer T4** (5×5 fits T4's maxFootprint=5)
- **Disc tier:** **T1** (cobblestone, water, oak, lantern→T2 if counted; keep lantern → **T2**)
- **Palette:** `minecraft:cobblestone`, `minecraft:cobblestone_wall`,
  `minecraft:water[level=0]`, `minecraft:oak_fence`, `minecraft:cobblestone_slab[type=top]`,
  `minecraft:lantern[hanging=true]`, `minecraft:chain`
- **Build:**
  - **Foundation (y=0):** 5×5 cobblestone ring with a 3×3 hollow center
    (`x,z ∈ 1..3` left empty); place `water[level=0]` in the 3×3 center at `y=0`.
    This is the visible water surface flush with the rim.
  - **Rim (y=1):** `cobblestone_wall` around the full 5×5 perimeter edge cells only
    (a low coping ring you can lean over) — wall blocks, not full blocks, so it reads
    as a well lip. Leave the 3×3 center open (water visible below).
  - **Posts (y=1..4):** four `oak_fence` posts at the four corners `(0,0),(4,0),(0,4),(4,4)`.
  - **Canopy (y=5):** 5×5 `cobblestone_slab[type=top]` roof resting on the four posts,
    leaving the sides open (classic village well silhouette).
  - **Lantern:** `chain` at `(2,4,2)` hanging from the slab center, `lantern[hanging=true]`
    at `(2,3,2)` below the chain — properly backed, hangs over the water.
- **Fixes vs current:** open sides (you can see/draw water), water flush with rim,
  lantern actually suspended from a chain to the canopy.

  - **Counter (y=1):** front-edge row `z=1`, `x=0..4`, `spruce_slab[type=top]` as a

  - **Light:** `chain` at `(2,3,0)` under the awning front, `lantern[hanging=true]`
    at `(2,2,0)`.
- **Fixes vs current:** continuous striped awning with proper stair transitions;
  red/white stripes (market read); lantern backed by chain.

## 5. Parametric helpers to add to the generator

These close the gaps that caused the current defects and enable the new shapes. All are
pure composition over `Blueprint.Builder.set` like the existing helpers.

1. **`gableEndFill(b, x0, z0, x1, z1, yBase, mat)`** — fills the two triangular gable
   ends (`z=z0` and `z=z1` faces) of a `gableRoofX` with wall material up to the ridge,
   so the attic is closed. **Fixes the open-gable defect across every gabled build.**
2. **`hipRoof(b, x0, z0, x1, z1, yBase, stair, capSlab)`** — a roof that slopes on all
   **four** sides (stairs facing inward on all four edges, stepping up to a ridge or
   point). Needed for `manor_house`, `emerald_market_hall`.
3. **`pyramidRoof(b, x0, z0, x1, z1, yBase, stair, cap)`** — square pyramid (4 slopes to
   a point). For `church` steeple, `lighthouse`/observatory caps, tower tops.
4. **`gambrelRoofX(...)`** — two-pitch-per-side barn roof. For `barn`.
5. **`circleRing(b, y, cx, cz, r, mat)`** / **`disc(b, y, cx, cz, r, mat)`** — midpoint-
   circle ring/filled disc at height `y`. For `lighthouse`, `windmill`, `copper_observatory`,
   round towers. (Skip-corner octagon is the cheap approximation the current windmill uses.)
6. **`dome(b, cx, cz, cy, r, mat)`** — stacked decreasing rings forming a hemisphere.
   For `copper_observatory`.
7. **`crenellate(b, y, x0, z0, x1, z1, wall)`** — perimeter battlement with a configurable
   merlon/crenel rhythm (default 2-up/1-gap), sitting flush on a wall top.
   **Fixes the floating-battlement defect**; for `watchtower`, `castle_keep`, towers.
8. **`door2(b, x, y, z, wood, wallFace)`** — door helper that derives `facing` from the
   wall face (`NORTH→south`, etc.). **Fixes the systemic door-facing bug.**
9. **`stripedBand(b, y, x0, z0, x1, z1, matA, matB, period)`** — alternating-material band,
   for lighthouse candy-stripes and market awnings.
10. **`window2(b, x, y, z, pane, sillMat)`** — pane plus an optional exterior sill
    stair/slab, so windows read with depth and always include glass.
11. **`chainLantern(b, x, y, z, hangLen)`** — a `chain`×N up to a backing block then a
    `lantern[hanging=true]`. **Fixes the floating-lantern defect** everywhere.
12. **`ramp(b, x0, z0, x1, z1, yStart, stair)`** — a walkable stair ramp between two
    heights. **Fixes the un-walkable bridge step.** For `stone_bridge`.
13. **`timberFrame(b, x0, z0, x1, z1, y0, y1, planks, log)`** — plank wall overlaid with
    a stripped-log stud/rail grid. For `manor_house`, `barn`.
14. **`copperPatina(level)`** — returns the cut-copper variant for a patina gradient
    (`cut_copper`→`exposed_`→`weathered_`→`oxidized_`). For `copper_observatory`,
    lighthouse cap.
